## Analysis

Your job is to build a **classification pipeline** that takes a recording, breaks it into windows, computes features, and assigns one of seven labels.


#### Two design axes

A2 has **two independent design choices**. Treat them separately in the report.

| Axis | What you choose | Example knobs |
|---|---|---|
| **Feature engineering** | Which features per window + window length | Time-domain stats (mean, std, RMS, range, percentiles), frequency-domain (dominant freq, spectral energy, FFT-peak ratio), window length (1s/3s/5s/10s), window overlap |
| **Model choice** | Which classifier + hyperparameters | Decision Tree, Random Forest, kNN, Logistic Regression, SVM, Gradient Boosting — anything sklearn classical. (Skip deep learning at A2 — classical models on window features are the right tool here.) |

Better features can let a simpler model win; a more powerful model can compensate for thin features. The report will ask you to think about both.

#### Required: compare at least 2 models

You must explore **at least two different classifier types** (e.g., Decision Tree vs Random Forest, kNN, Logistic Regression, etc.) and compare them on the same feature set. This makes "model choice" an explicit decision you document, not a hidden one.

## FAQ

**Q: Can I use ChatGPT/Claude to write the notebook and the exploration report?**
Yes. You're being assessed on understanding, not typing. The quiz catches faking.

**Q: Can I use deep learning (CNN, LSTM, etc.)?**
Skip it for A2. Hand-crafted window features + classical ML is the right tool for this class set; deep learning is overkill and the GPU/setup overhead isn't worth it. A3 will allow more powerful models if you want.

**Q: How do I aggregate window predictions to a recording-level label?**
Majority vote is fine. You can also try duration-weighting (longer-running classes get higher weight) or confidence-weighting. Document your choice in §3.

**Q: What window length should I use?**
Try several. A few seconds typically works for gait-based activities, but longer windows can capture rest patterns. Report what you tried in §1.

**Q: Why does the baseline confuse stairs and walking?**
Stairs-up has a vertical impulse pattern similar to walking but with different amplitude and timing. Without features that capture vertical-axis specifics or step periodicity changes, the classifier can't tell them apart. Your job is to fix this.

**Q: Why are lying, sitting, and standing so hard to separate?**
Sensor Logger removes gravity, so the phone's orientation (flat vs upright) is not in the data. All three look like "almost no motion" on the acceleration magnitude. Think about what is still different (e.g., body sway while standing, small movements while sitting), and expect some confusion between these classes. Explain what you see in §4.
